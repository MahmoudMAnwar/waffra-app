# وفرة — اختبار الاعتماد على هاتفين فعليين (قبل Production)

**الحالة:** نموذج اختبار غير منفّذ حتى الآن. نجاح Flutter / Firebase emulator / APK لا يعني اجتياز هذا النموذج.

المطلوب: هاتفان Android حقيقيان، إصدار APK موقّع **من نفس SHA**، حساب Firebase اختباري، وبيانات معاملات وهمية فقط. لا تستخدم الرسائل البنكية أو المرفقات الشخصية.

## قبل أي اختبار
- [ ] ثبت آخر APK تجريبي من GitHub Actions على هاتف اختبار فقط بعد أخذ نسخة آمنة من بياناته.
- [ ] راجع SHA256 للملف والتوقيع وتطابق اسم الحزمة `com.waffra.app` مع إعدادات Firebase.
- [ ] Android 16 / API 36 وAndroid آخر بإصدار مختلف إذا توفر، للوصول لأوسع تغطية.
- [ ] سجّل SHA الإصدار، Build Run ID ونتائج كل حالة فقط؛ **ممنوع** رفع رقم هاتف أو اسم مستخدم أو نص رسالة أو مبلغ حقيقي.
- [ ] اختبار تثبيت وتشغيل أولي بالأمر `WAFFRA_QA_DEVICE_CONFIRMED=YES bash scripts/m108_android_device_smoke.sh /path/to/app-release.apk SERIAL` على جهاز مخصص للاختبار.

## المجموعة A: المصدر والتخزين
- [ ] أول تشغيل نظيف بدون بيانات لا يصنع عمليات مالية من تلقاء نفسه.
- [ ] إدخال 5 رسائل تجريبية (2 دخل، 3 مصروفات) مرة واحدة، مع تأكيد. التحقق من 5 عمليات فقط.
- [ ] تكرار اللصق يرفض الازدواج، إلا عند موافقة صريحة وفق السلوك المعتمد.
- [ ] إغلاق التطبيق وإعادة تشغيله يحافظ على نفس العمليات والأقسام والأهداف والمرفقات.
- [ ] فتح Widget وإضافة معاملة تجريبية، العودة إلى Home؛ نفس الرصيد، بدون تكرار.
- [ ] إضافة من Widget وHome بسرعة، اختبار انقطاع التطبيق في الحفظ، دون سقوط أو فقد.
- [ ] إنشاء/تعديل/حذف/استرجاع قسم، هدف ادخار، متكررة وملف إيصال، مع المحافظة على التاريخ.
- [ ] لا يتم التحويل إلى SQLCipher إلا بعد أن يثبت خادم الترحيل كل الـ24 route ومفاتيح النسخ والاسترجاع؛ قبل ذلك يجب وقف النسخة الإنتاجية.

## المجموعة B: مزامنة واسترجاع سحابي بين هاتفين
- [ ] مستخدم اختباري واحد يسجل الدخول على الجهاز A ثم الجهاز B.
- [ ] على A يفعّل المزامنة صراحة ويحفظ رمز الاسترجاع خارج التطبيق.
- [ ] إضافة فئات ومعاملات وأهداف وفاتورة وهمية ثم نشر سجلات مشفرة فقط.
- [ ] على B يسترجع عبر الرمز بعد طلب صريح؛ يطابق العدّ والهوية والمبلغ الوهمي بدون إنشاء سجل جديد.
- [ ] على A وB تعديل نفس معاملة أثناء وضع Offline؛ يجب وجود تعارض واضح، لا last-write-wins صامت.
- [ ] تلف رمز الاسترجاع أو مفتاح غير صحيح يمنع فتح البيانات؛ لا ينشئ قاعدة فارغة.
- [ ] انقطاع الإنترنت قبل فهرس manifest لا يظهر نسخة استرجاع ناقصة.
- [ ] حذف الحساب على A يمنع B من إعادة إنشاء النسخة السحابية بجلسة قديمة.
- [ ] لا يجوز اعتبار الميزة ناجحة قبل نشر الخدمة المتوافقة وبعد تفعيل المستخدم الحقيقي ونتائج الاختبار.
