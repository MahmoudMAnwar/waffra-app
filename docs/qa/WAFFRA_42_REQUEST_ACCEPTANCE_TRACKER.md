## سياسة التسليم

- إصدار APK من `main` فقط وبعد نجاح الاختبارات على نفس SHA.
- لا يعتبر النجاح على GitHub بديلًا عن معاينة الشاشة واختبار التحديث دون فقد بيانات.
- افتح أو حدّث PR واحد للحزمة؛ لا دمج قبل إغلاق البنود المطلوبة والرجوع للمستخدم بشأن غير المكتمل.
- لا تغير الوظائف السابقة غير المطلوبة، ولا تحول اختبارًا سلبيًا إلى نتيجة نجاح مزيفة.
- عند كل تقرير اذكر: منفذ بالكود / ناجح CI / فاشل / متبقٍ، والأعداد بالـWorkflow منفصلة عن العيوب الفريدة.

## تحديث تنفيذ M392–M395

- حالة هذه البنود «كود مضاف» لا تعني قبولًا نهائيًا؛ لا تزال اختبارات GitHub واختبارات الجهازين ضرورية.
- الادخار المفتوح مستهدفه الصفر في نموذج المبالغ، مع عدم قبول الأرقام السالبة. مسارات SQLCipher التجريبية القديمة تحتاج تدقيق ترقية جداولها قبل أي تحويل إنتاجي؛ لا تبديل لمصدر المستخدم المالي.
- مرجع المرفقات في شارة المعاملة يستخدم العارض الموجود نفسه من غير نقل صور، والإجراءات السريعة لا تعيد تخصيص رصيد الهدف.
